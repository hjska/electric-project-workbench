# 技术方案与开发计划

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面壳 | **Electron** | 打包 exe 成熟，内置 Chromium 渲染，界面还原度高，前端技术栈任意 |
| 前端框架 | **React 18 + TypeScript + Vite** | 生态成熟、类型安全、热更新快 |
| UI 库 | **Ant Design 5** | 表格/表单/弹窗组件齐全，中文文档好，适配管理类系统 |
| 状态管理 | **Zustand** | 轻量，无需 Redux 样板代码 |
| 图表 | **ECharts** | 仪表盘图表需求全覆盖 |
| 数据库 | **better-sqlite3** | 同步 API 简洁，性能好，单文件，Electron 兼容成熟 |
| 数据访问 | 主进程直接写 SQL（轻量 DAO 层） | 单机无并发，无需 ORM |
| Excel 导入导出 | **SheetJS (xlsx)** | 纯 JS，前后端通用 |
| 打包 | **electron-builder** | 生成 Windows exe / 安装包 |
| 进程通信 | Electron IPC（preload 暴露安全 API） | 渲染进程不直接碰 Node/文件系统 |

> 备选方案：若不喜欢 Electron 体积，可用 **Tauri (Rust)** 打包，体积小很多，但需装 Rust 工具链。当前选 Electron 因生态成熟、排错成本低。

## 2. 架构设计

```
┌─────────────────────────────────────────────┐
│  Renderer (React + AntD)  —— 所有页面/交互    │
│      │  window.api.xxx  (contextBridge)      │
├──────┼──────────────────────────────────────┤
│  Preload  —— 白名单 API 暴露，无 Node 权限    │
├──────┼──────────────────────────────────────┤
│  Main Process (Node)                         │
│    ├── IPC Router  —— 按 channel 分发         │
│    ├── Service 层  —— 业务规则校验(R1~R16)     │
│    ├── DAO 层      —— SQL 封装(参数化查询)     │
│    └── better-sqlite3 → data/app.db          │
└─────────────────────────────────────────────┘
```

**安全原则**
- `contextIsolation: true`、`nodeIntegration: false`。
- 所有 SQL 使用参数绑定（`?` 占位），杜绝拼接注入。
- 所有用户输入在渲染层做转义/校验，主进程再做一次业务校验（双保险）。

## 4. 开发里程碑

| 阶段 | 内容 | 交付物 | 验收点 |
|---|---|---|---|
| **M1 骨架** | Electron+React+Vite 工程搭建、SQLite 初始化建表、IPC 通路打通 | 可运行的空壳应用，能读写一条测试数据 | 双击启动成功，读写出数据 |
| **M2 项目台账** | P1/P2 项目列表与详情、M1 全部字段与规则 | 可增删改查项目 | 编号唯一、日期校验生效 |
| **M3 设备物料** | P3 设备清单、Excel 导入导出 | 设备管理完整可用 | 导入去重生效，状态流转正确 |
| **M4 工序与日报** | P4/P5 工序与日报，派生数据自动重算 | 核心业务闭环 | 日报保存后完成率自动更新 |
| **M5 里程碑与问题** | P6/P7 | 里程碑与问题台账可用 | 逾期标红、闭环校验生效 |
| **M6 附件管理** | P8-1 附件上传/预览/删除，文件落盘 `data/attachments/` | 附件模块可用 | 大文件拦截生效，删除记录同步删物理文件 |
| **M7 仪表盘与报表** | P0 仪表盘、P8 导出、P9 备份（手动+每日定时） | 统计与导出可用 | 导出 Excel 打开正常，自动备份按计划触发并可恢复 |
| **M8 打磨打包** | 空状态/错误兜底/性能优化、electron-builder 打包 | 可分发 exe | 拷贝到新机器可直接运行 |

> 每个阶段结束都是一个可运行、可验证的版本（增量交付），不会出现"做到一半跑不起来"。

## 5. 打包与交付

- 开发运行：`npm run dev`
- 本地构建：`npm run build && npm run dist` → 输出 `release/电气项目管理 Setup x.x.x.exe`
- 免安装版：同时输出 `release/win-unpacked/` 目录，压缩后可直接拷贝使用。
- 数据库随应用目录走：`data/app.db`，升级安装包不影响已有数据（安装程序不覆盖 data 目录）。

## 6. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| better-sqlite3 原生模块编译失败 | 无法打包 | 预编译二进制 + electron-rebuild；失败则切 `sql.js`（纯 WASM，性能略低） |
| Excel 模板列对不上导致导入失败 | 数据录入受阻 | 提供模板下载 + 导入预览 + 错误行提示 |
| 数据误删无法找回 | 数据损失 | 强制周期性备份提醒 + 删除二次确认 + 软删除标记（可选增强） |
| 甘特图开发成本高 | 影响工期 | 列为二期，本期用进度条替代 |
| 需求后期扩张 | 返工 | 文档 05 列出待确认项，先锁定范围再开发 |
