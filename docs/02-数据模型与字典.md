# 数据模型与数据字典

> 存储引擎：SQLite 3 ｜ 文件：`data/app.db` ｜ 字符集：UTF-8

## 1. 实体关系（ER 概览）

```
project 1───n equipment
project 1───n process ──1───n daily_report
process 1───n process_link (前置关系, 自关联)
project 1───n milestone ──n──n process (关联工序)
project 1───n issue
project 1───n attachment ──> 多态关联(project/equipment/process/issue)
```

- 所有业务表均以 `project_id` 为归属键，删除项目时级联删除。
- **例外**：`equipment.project_id` 允许为空，空值代表「日常备品」（不归属项目的公共备件），
  不属于任何项目、也不参与级联删除（详见 2.2）。
- 主键统一使用自增整数 `id`；`project.code` 为业务唯一键。

## 2. 表结构定义（DDL）

### 2.1 project — 项目表

```sql
CREATE TABLE project (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  code          TEXT    NOT NULL UNIQUE,          -- 项目编号
  name          TEXT    NOT NULL,                 -- 项目名称
  address       TEXT,                             -- 项目地址
  owner_unit    TEXT,                             -- 建设单位
  build_unit    TEXT,                             -- 施工单位
  supervise_unit TEXT,                            -- 监理单位
  manager       TEXT    NOT NULL,                 -- 项目经理
  phone         TEXT,                             -- 联系电话
  contract_amount REAL,                           -- 合同金额(元)
  start_date    TEXT    NOT NULL,                 -- 开工日期 YYYY-MM-DD
  plan_end_date TEXT    NOT NULL,                 -- 计划竣工
  actual_end_date TEXT,                           -- 实际竣工
  status        TEXT    NOT NULL DEFAULT '未开工', -- ENUM-01
  remark        TEXT,
  folder_path   TEXT,                             -- 项目资料文件夹绝对路径（v2 新增）
  created_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_project_status ON project(status);
```

> **v2 变更**：新增 `folder_path`，记录该项目的工程资料文件夹（图纸/程序/资料存放处）。
> 由 `folder.service` 维护，不在项目表单里编辑。迁移脚本见 `electron/db/index.ts` 的 `migrate()`，
> 对老库执行 `ALTER TABLE project ADD COLUMN folder_path TEXT`，`meta.schema_version` 升为 `2`。

### 2.2 equipment — 设备物料表

```sql
CREATE TABLE equipment (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id    INTEGER REFERENCES project(id) ON DELETE CASCADE,  -- NULL = 日常备品（v3 起可空）
  name          TEXT    NOT NULL,                 -- 设备名称
  model         TEXT,                             -- 规格型号
  tag_no        TEXT,                             -- 设备编号/位号
  brand         TEXT,                             -- 品牌/厂家
  supplier      TEXT,                             -- 供货商
  unit          TEXT    NOT NULL DEFAULT '台',     -- ENUM-05
  quantity      REAL    NOT NULL CHECK(quantity > 0),
  unit_price    REAL    DEFAULT 0 CHECK(unit_price >= 0),
  contract_arrival_date TEXT,                     -- 合同到货日期
  actual_arrival_date   TEXT,                     -- 实际到货日期
  arrival_status TEXT   NOT NULL DEFAULT '未到货', -- ENUM-02
  accept_status  TEXT   NOT NULL DEFAULT '未验收', -- ENUM-03
  location      TEXT,                             -- 存放位置
  remark        TEXT,
  created_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_equip_project ON equipment(project_id);
CREATE INDEX idx_equip_arrival ON equipment(arrival_status, accept_status);
-- 自然键唯一：必须用 IFNULL(project_id,0)。SQLite 的唯一索引把 NULL 视为互不相等，
-- 直接写 project_id 会让「日常备品」可以无限重复插入。
CREATE UNIQUE INDEX uk_equip_natural ON equipment(IFNULL(project_id,0), name, IFNULL(model,''));
```

> **v3 变更**：`project_id` 放开为可空，空值 = **日常备品**（暂不归属任何项目的公共备件/库存）。
> 这类记录只出现在「物料管理」里，不计入任何项目的设备清单、进度与到货率。
> SQLite 没有「ALTER COLUMN 去掉 NOT NULL」的语法，迁移采用**重建表**：
> 建新表 → 按列交集拷数据 → 改名 → 重建索引，整体在事务内完成，`meta.schema_version` 升为 `3`。
> 指向 project 的外键与 `ON DELETE CASCADE`（删项目清设备）语义保持不变，
> 且删除项目**不会**影响备品。迁移实现见 `electron/db/index.ts` 的 `migrateSchema()`，
> 冒烟测试含「v2 老库升级到 v3」的专项断言。

### 2.3 process — 工序表

```sql
CREATE TABLE process (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id    INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
  seq_no        INTEGER NOT NULL DEFAULT 0,       -- 工序序号(排序)
  name          TEXT    NOT NULL,                 -- 工序名称
  plan_qty      REAL    NOT NULL DEFAULT 0,       -- 计划总量
  qty_unit      TEXT    NOT NULL DEFAULT '项',     -- ENUM-05
  done_qty      REAL    NOT NULL DEFAULT 0,       -- 累计完成量(系统维护)
  plan_start    TEXT    NOT NULL,
  plan_end      TEXT    NOT NULL,
  actual_start  TEXT,
  actual_end    TEXT,
  weight        REAL    NOT NULL DEFAULT 1,       -- 进度权重
  owner         TEXT,                             -- 负责人
  status        TEXT    NOT NULL DEFAULT '未开始', -- ENUM-04
  remark        TEXT,
  created_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_process_project ON process(project_id, seq_no);
```

### 2.4 process_link — 工序前置关系（多对多）

```sql
CREATE TABLE process_link (
  process_id     INTEGER NOT NULL REFERENCES process(id) ON DELETE CASCADE,
  pre_process_id INTEGER NOT NULL REFERENCES process(id) ON DELETE CASCADE,
  PRIMARY KEY (process_id, pre_process_id)
);
```

### 2.5 daily_report — 进度日报表

```sql
CREATE TABLE daily_report (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id    INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
  process_id    INTEGER NOT NULL REFERENCES process(id) ON DELETE CASCADE,
  report_date   TEXT    NOT NULL,                 -- 日报日期 YYYY-MM-DD
  day_qty       REAL    NOT NULL,                 -- 当日完成量
  cum_qty       REAL    NOT NULL DEFAULT 0,       -- 累计完成(保存时计算)
  unit          TEXT    NOT NULL DEFAULT '项',     -- ENUM-05
  weather       TEXT,                             -- ENUM-06
  worker_count  INTEGER DEFAULT 0,                -- 出勤人数
  recorder      TEXT,                             -- 记录人
  site_note     TEXT,                             -- 现场情况
  created_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE UNIQUE INDEX uk_report_proc_date ON daily_report(process_id, report_date);
CREATE INDEX idx_report_project_date ON daily_report(project_id, report_date);
```

### 2.6 milestone — 里程碑表

```sql
CREATE TABLE milestone (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id    INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
  name          TEXT    NOT NULL,
  plan_date     TEXT    NOT NULL,
  actual_date   TEXT,
  status        TEXT    NOT NULL DEFAULT '未开始', -- ENUM-07
  description   TEXT,
  created_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime'))
);
```

### 2.7 milestone_process — 里程碑关联工序

```sql
CREATE TABLE milestone_process (
  milestone_id INTEGER NOT NULL REFERENCES milestone(id) ON DELETE CASCADE,
  process_id   INTEGER NOT NULL REFERENCES process(id) ON DELETE CASCADE,
  PRIMARY KEY (milestone_id, process_id)
);
```

### 2.8 issue — 问题记录表

```sql
CREATE TABLE issue (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id    INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
  process_id    INTEGER REFERENCES process(id) ON DELETE SET NULL,
  description   TEXT    NOT NULL,                 -- 问题描述
  severity      TEXT    NOT NULL DEFAULT '一般',   -- ENUM-08
  reporter      TEXT,                             -- 提出人
  report_date   TEXT    NOT NULL,
  owner         TEXT,                             -- 责任人
  due_date      TEXT,                             -- 要求闭环日期
  status        TEXT    NOT NULL DEFAULT '待处理', -- ENUM-09
  solution      TEXT,                             -- 处理措施
  close_date    TEXT,                             -- 闭环日期
  created_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_issue_project_status ON issue(project_id, status);
```

### 2.9 attachment — 附件/图片表

```sql
CREATE TABLE attachment (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id    INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
  ref_type      TEXT    NOT NULL,                 -- ENUM-10 关联对象类型
  ref_id        INTEGER,                          -- 关联记录 id(项目级为 NULL)
  file_name     TEXT    NOT NULL,                 -- 原始文件名
  rel_path      TEXT    NOT NULL UNIQUE,          -- 相对路径 attachments/{project_id}/xxx
  file_ext      TEXT,                             -- 扩展名(小写,不含点)
  file_size     INTEGER NOT NULL DEFAULT 0,       -- 字节
  category      TEXT    NOT NULL DEFAULT '其他',   -- ENUM-11 照片/图纸/文档/其他
  description   TEXT,                             -- 说明
  created_at    TEXT    NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_attach_project ON attachment(project_id);
CREATE INDEX idx_attach_ref ON attachment(ref_type, ref_id);
```

> 存储策略：**文件本体不进数据库**。上传时复制到 `data/attachments/{project_id}/{uuid}.{ext}`，库内只存相对路径，保证整包拷贝可迁移。删除记录时同步删除物理文件。

## 3. 枚举字典

| 编号 | 名称 | 取值 |
|---|---|---|
| ENUM-01 | 项目状态 | 未开工 / 施工中 / 已竣工 / 已暂停 / 已取消 |
| ENUM-02 | 到货状态 | 未到货 / 部分到货 / 已到货 |
| ENUM-03 | 验收状态 | 未验收 / 合格 / 不合格 / 让步接收 |
| ENUM-04 | 工序状态 | 未开始 / 进行中 / 已完成 / 已暂停 |
| ENUM-05 | 计量单位 | 台 / 套 / 个 / 米 / 千米 / 项 / 批 / 百分比 |
| ENUM-06 | 天气 | 晴 / 多云 / 阴 / 小雨 / 大雨 / 雪 / 大风 |
| ENUM-07 | 里程碑状态 | 未开始 / 进行中 / 已达成 / 已延期 |
| ENUM-08 | 问题严重等级 | 一般 / 重要 / 紧急 |
| ENUM-09 | 问题状态 | 待处理 / 处理中 / 已闭环 |
| ENUM-10 | 附件关联类型 | 项目 / 设备 / 工序 / 问题 |
| ENUM-11 | 附件分类 | 照片 / 图纸 / 文档 / 其他 |

> 枚举值统一以文本存储（非数字），便于直接阅读与导出；前端下拉选项与字典保持一致。

## 4. 计算规则（派生数据）

| 指标 | 公式 | 说明 |
|---|---|---|
| 工序完成率 | `min(done_qty / plan_qty, 1)` | plan_qty=0 时按"状态=已完成"取值 100%，否则 0 |
| 项目加权进度 | `Σ(工序完成率 × weight) / Σ(weight)` | 仅统计非"已暂停"工序 |
| 设备到货率 | `已到货 + 部分到货×0.5` / 设备总条数 | 部分到货按半计入 |
| 验收合格率 | 验收合格数 / 已到货数 | 分母为 0 时显示"—" |
| 逾期工序 | `status != '已完成' AND plan_end < 今天` | 列表标红 |
| 逾期问题 | `status != '已闭环' AND due_date < 今天` | 列表标红 |
| 待闭环问题数 | `status != '已闭环'` 的计数 | 仪表盘指标 |

## 5. 数据完整性约束清单

| 约束 | 实现层 | 说明 |
|---|---|---|
| 项目编号唯一 | DB UNIQUE + 前端预校验 | |
| 计划竣工 ≥ 开工日期 | 前端 + 保存前校验 | |
| 设备自然键唯一 | DB 唯一索引（project+name+model） | 防重复导入 |
| 数量 > 0 | DB CHECK + 前端 | |
| 同一工序同日仅一条日报 | DB 唯一索引 + 前端覆盖提示 | |
| 已闭环问题必填处理措施 | 前端表单规则 | |
| 删除项目级联清理 | DB ON DELETE CASCADE | |

## 6. 备份与迁移

- **手动备份**：应用内"立即备份"= 关闭写连接 → 复制 `app.db` 到用户选定目录，文件名 `backup_{YYYYMMDD_HHmmss}.db`。
- **定时自动备份**：应用启动时注册定时器，每天一次（默认 18:00，可配置）自动执行备份，备份目录默认 `data/backups/`，**保留最近 30 份**，超出按时间最旧的自动清理。
- **完整备份包**：因附件存于 `data/attachments/`，完整备份 = `app.db` + `attachments/` 目录，打包为 `backup_{时间戳}.zip` 存放。
- **恢复**：选择备份文件（.db 或 .zip）→ 覆盖 `app.db` 及 `attachments/` → 重启应用（二次确认警告）。
- **迁移**：整个应用目录（含 `data/`）拷贝到新机器即可，无路径硬编码之外的环境依赖。（路径以应用目录为基准，用相对路径解析。）
- **版本升级**：`meta.schema_version` 记录版本，升级时按版本号顺序执行迁移脚本。
